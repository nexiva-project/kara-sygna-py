## 🌿 Padrão de Nomenclatura de Branches

Utilizamos o padrão de prefixos diretos `tipo/assunto-ou-tarefa` para manter o histórico de desenvolvimento e aprendizado organizado.

### 📂 Tipos de Branches

| Prefixo | Finalidade | Exemplo Prático |
| :--- | :--- | :--- |
| `study/` | Estudos gerais, teorias, anotações ou exercícios de cursos | `study/flexbox-basics` |
| `feat/` | Desenvolvimento de uma nova funcionalidade no projeto | `feat/camera` |
| `test/` | Criação, estudo ou correção de testes automatizados | `test/user` |
| `chore/` | Configurações do projeto, instalação de pacotes ou tarefas repetitivas | `chore/setup-eslint` |
| `fix/` | Correção de bugs ou erros no código | `fix/api-connection` |
| `docs/` | Alterações exclusivas na documentação (como este README) | `docs/update-readme` |
| `refactor/` | Melhoria na estrutura do código sem alterar o que ele faz | `refactor/clean-functions` |
| `experiment/` | Testes rápidos de ferramentas ou códigos que podem ser descartados | `experiment/tailwind-v4` |

### 📝 Boas Práticas
* **Letras minúsculas:** Escreva todo o nome da branch em minúsculo.
* **Separação por hífen:** Use `-` no lugar de espaços (ex: `feat/perfil-usuario`).
* **Seja direto:** Use nomes curtos que expliquem claramente o objetivo da branch.
